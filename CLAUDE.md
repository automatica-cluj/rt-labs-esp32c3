# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Teaching material for the UTCN Real-Time Systems lab: a standalone track of five
labs on an **ESP32-C3 Super Mini** (single-core RISC-V, 160 MHz),
programmed with the **Arduino core 3.x** (tested 3.3.7). The sketches call the
FreeRTOS API directly. The equipment is the board and USB only: all timing
comes from `esp_timer_get_time()`, the cycle counter and hardware timers,
reported over USB CDC serial. The one exception is optional: Lab 1's
`periodic_jitter` also drives GPIO0 (periodic task computing) and GPIO1 (hog
job running) for a logic analyzer, and its README has a section on reading
them in Saleae Logic 2. The sibling Linux/PREEMPT_RT track lives in
`../rt-labs-linux`, and its style is followed here.

Layout: `labN-topic/README.md` plus sketch folders `labN-topic/<name>/<name>.ino`,
each holding a **copy** of `common/rt.h`. `docs/` has the setup guide, the
Arduino overview, the FreeRTOS concepts page and the C primer (practical,
English). The theory pages
(Romanian) are in the separate `../rt-concepts` repository, and each lab README
links to its pages there. `tools/` has the sync, compile, hardware-in-the-loop
and plot scripts. `tutor/` has the lab helper: `rules.md` (instructions for
the assistant, hand-written) and `tutor_bundle.md` (generated by
`tools/make_tutor_bundle.sh`: rules plus every README, doc, `rt.h` and
sketch), which students attach to a chat.

## Build and test

```bash
make sync                    # copy common/rt.h next to every .ino
make compile                 # sync, then compile every sketch with --warnings all (no board)
make hil PORT=/dev/cu.usbmodemXXXX                       # flash every sketch, press its keys, check verdicts
make hil PORT=/dev/cu.usbmodemXXXX ONLY="race inversion" # only these sketches (folder basenames)
```

One sketch without the Makefile (same settings as `compile_all.sh`):

```bash
ARDUINO_DIRECTORIES_USER=$PWD/.arduino-user arduino-cli compile \
  --fqbn esp32:esp32:esp32c3:CDCOnBoot=cdc --warnings all lab5-shared-resources/race
```

- The scripts find `arduino-cli` on PATH or inside the macOS Arduino IDE
  bundle. `ARDUINO_CLI` and `FQBN` override the defaults.
- They set `ARDUINO_DIRECTORIES_USER=.arduino-user`, because the CLI hangs on
  the macOS privacy check when it touches `~/Documents/Arduino`.
- Warnings from the core's own headers are ignored; warnings in `.ino` or
  `rt.h` fail the build. A stale `rt.h` copy fails it too
  (`sync_common.sh --check`).
- `make hil` needs a board and `pyserial` (a virtual environment is fine:
  `python3 -m venv .venv && .venv/bin/pip install pyserial`, then run
  `.venv/bin/python tools/hil_smoke.py --port ...`). The full serial output of the run
  goes to `hil_smoke.log`. There are no other tests.
- `tools/plot_serial.py run.log [out.png]` (needs matplotlib) plots the
  `csv: k,...` / `csv: end` block that `periodic_jitter` prints on key `p`.

## How the pieces fit

- `common/rt.h` is the whole shared library: header-only, `static inline`
  functions, one global `struct rt_timeline g_tl`. It gives clocks (`rt_now_us`, `rt_cycles`), the absolute sleep `rt_sleep_until_tick`,
  calibrated busy work (`rt_busy_us`, `rt_tl_busy`), `rt_start_task`, `struct rt_stats`,
  the timeline strip, `rt_read_key` and `verdict`. The Arduino IDE only finds
  headers next to the `.ino`, hence the copies. Both scripts pick sketches up
  with the glob `lab*/*/*.ino`, so a new sketch folder is synced and compiled
  with no further registration.
- `rt_verdict()` prints `VERDICT: <text>`, and that line is the contract between
  a sketch, its README and `tools/hil_smoke.py`. For each entry in `CHECKS`
  the harness sends the key, then judges the **first** line that starts with
  `VERDICT:` against a regex. A second or stray verdict line is therefore
  read as the answer to the next key. The harness reopens the port if the
  board resets (the `starvation_wdt` variants that reset on purpose), and
  the key order in `CHECKS` is the order they are run in.
- `rt_begin()` waits up to 3 s for the serial monitor, then calibrates
  `rt_busy_us()` at priority 20 with interrupts off. The harness sleeps 3.5 s
  after opening the port for this reason.
- A new sketch needs: its folder and `.ino`, `make sync`, a section in the lab
  README, a row entry in the root `README.md` table, and a `CHECKS` entry.

## Conventions

- Edit `common/rt.h` only, then run `make sync`. Never edit a copy.
- Sketches are compiled as C++ by Arduino, but the code is written as plain
  C, to match the Linux track (`../rt-labs-linux`, `rt.h`
  there): no references, default arguments, unnamed parameters, `std::`,
  lambdas, templates or classes. Structs are passed by pointer, types are
  spelled `struct Name`, every helper is prefixed `rt_`. `<stdatomic.h>` does
  not compile in Arduino's C++ mode, so Lab 5 uses `__sync_fetch_and_add` on a
  plain `uint32_t`. `docs/c_for_these_labs.md` explains what students meet;
  keep that page in sync.
- **Arduino prototype trap:** the IDE generates function prototypes above
  user type declarations, so functions must not take enums declared in the
  sketch. Use `int` constants. Structs declared before use have worked.
- Each sketch: header comment listing the keys, a `// ---- EXPERIMENT KNOBS ----`
  block, `rt_begin()` in `setup()`, variants selected by single keys in
  `loop()`, and one `VERDICT: ...` line per experiment.
- Nothing is printed inside timing loops. Tasks record into static arrays and
  `loop()` prints afterwards.
- Lab task priorities stay within 1–20 (esp_timer 22, Wi-Fi 23). The control
  code in `loop()` raises itself (usually to 10) while it releases tasks.
- `rt_busy_us()` is iteration-based CPU time, calibrated at start-up with
  interrupts off, so preemption stretches it the way real computation would.
- **`xTaskDelayUntil` trap:** its `prev` argument must be a tick in the past.
  A `prev` later than now is read as a wrapped tick counter and the call
  returns at once. To sleep until an absolute tick use `rt_sleep_until_tick()`.
  This bug made `rm_taskset` starve two of its three tasks until it was run on
  a board, so run `make hil` after changing timing code; `make compile` cannot
  catch this kind of error.
- Keep `portENTER_CRITICAL` sections far below 300 ms (the interrupt watchdog).
  The task watchdog is 5 s and does not watch the idle task.
  `starvation_wdt` shortens it to 3 s and adds `loopTask` on purpose.
- READMEs: goal and time, numbered sections, lettered experiments with the
  sketch key(s) in the heading, as in ``Experiment F — overload (key `c`)``.
  The labs are observation only: each experiment says what the key does, then
  **Look at** (which output lines) and **What it shows** (the explanation,
  given rather than asked). No questions for students, no separate Questions
  section. Plain prose, no emojis. They describe what to look for and
  contain no fabricated numbers. Captured output from a real board may be
  added.
- The theory pages (Romanian, theory only, platform-neutral) live in the
  separate repository `../rt-concepts`
  (https://github.com/automatica-cluj/rt-concepts), shared with the Linux
  track. Its `CLAUDE.md` has the writing rules. Each lab README here has a
  "Theory behind this lab" line that links to its pages by full GitHub URL, so
  renaming a page there breaks the link here silently: keep both in step.
- When changing a sketch, update its README and the expected verdicts in
  `tools/hil_smoke.py`.
- `make compile` rebuilds `tutor/tutor_bundle.md`. Commit it with any change
  to a README, a doc, `common/rt.h` or a sketch, so the lab helper matches
  the labs.
